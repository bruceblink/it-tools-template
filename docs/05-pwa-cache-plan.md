# 应用壳预缓存与访问后离线缓存

计划日期：2026-10-15。实施日期：2026-10-16。承接 [开发计划](01-development-plan.md) 的第三阶段；第二阶段已提交后实施本片。

## 当前证据与范围

本轮安全批次的最终生产构建列出 325 个预缓存文件，合计 23378.87 KiB。后续实施时需要重新测量构建。工具组件已有路由懒加载，但 Workbox 又把全部 JavaScript 和 CSS 加入首次预缓存。最大的候选资源包括 TypeScript worker、MAC 厂商数据和 Text Diff；这些体积来自构建清单，不等同于实际传输量。

本片实现应用壳（Application Shell）的预缓存边界，以及访问后静态资源的运行时缓存（Runtime Cache）。应用壳指入口 HTML、入口的静态 JavaScript 依赖、样式、字体和启动图标。动态工具入口及其专属依赖不进入首次预缓存。运行时缓存只处理同源、构建生成的静态资源，不保存用户内容、工具页面 URL 或第三方响应。

## 实施顺序与验收条件

1. 输出 Vite 构建清单。从 `index.html` 入口递归收集静态 `imports`、CSS 和 assets，去重并排除 `dynamicImports`。用依赖关系筛选 Workbox 候选清单，保留应用启动图标和导航回退入口，不依赖 chunk 名称猜测。
2. 为访问过的同源构建资源增加有数量上限的运行时缓存。保留内容哈希资源的更新边界；升级后清理过期缓存。网络或缓存写入失败不得伪造离线成功。
3. 生成体积报告，明确原始字节和 gzip 字节。首次预缓存原始大小不得超过 8 MiB。报告首屏静态 JavaScript gzip、各可选工具的完整静态闭包和从已载入应用壳打开工具时新增的 JavaScript gzip；Worker 脚本在运行资源报告中单独列出。300 KiB 与 500 KiB 的长期目标保留，超标项逐项处理，不调高目标。
4. 增加清单依赖、去重、路径边界、预算失败和缺失资源的定向测试。为生产构建增加离线行为验收：新浏览器首页不下载 MAC、Text Diff 或 Monaco worker；首页可离线重载；联网访问和实际使用过的代表工具可在断网后重载。
5. 通过最终检查后提交并推送。继续检查首屏和大型工具的预算，不把本片完成写成整个第三阶段完成。

### 构建与缓存边界

- 启用 Vite manifest，从 `index.html` 递归收集静态 imports、CSS 和 assets。工具的动态入口不进入应用壳。PWA 注册助手在应用挂载后再动态加载，不进入首屏或离线应用壳。首次注册仍需一次在线页面加载；注册完成后，Service Worker 继续提供缓存资源的离线访问。
- PWA 改为 `injectManifest`，继续生成原来的 `sw.js` 地址。Workbox 候选清单按应用壳筛选，图标和 manifest 纳入测量；插件在转换后追加的 manifest 条目只计一次。缺失依赖、越界路径、符号链接逃逸或缺失文件都会让构建失败。
- 静态依赖图之外，扫描本次 `assets/` 的实际构建文件，生成精确的运行时白名单，包含 Worker 和字体。只缓存同源、无查询参数的 GET；仅接收 HTTP 200 且非 HTML 的响应。工具页面 URL、请求内容、第三方资源、未生成的路径及带参数请求不进入工具缓存。
- 使用 Cache First，每个版本和 Service Worker scope 最多 160 个资源、有效期 30 天，遇到存储配额不足允许清理。版本由构建文件清单生成，新版激活时只移除当前 scope 的旧工具缓存。Workbox 负责应用壳预缓存的更新和过期条目清理。
- 工具只有在联网访问并实际加载所需资源后才具备对应离线能力。过期、容量淘汰、浏览器清理或缺失的资源仍会产生实际网络失败；不把应用 HTML 伪装成缺失的脚本响应。

### 体积报告与后续目标

`dist/bundle-report.json` 输出唯一资源的原始与 gzip 字节、首屏启动 JavaScript、首页全部可选入口的静态依赖闭包，以及运行时构建资源。可选入口按首页的真实 `dynamicImports` 收集，因此也包含打包器合并后的工具入口。工具闭包包含共享应用资源，表示完整静态依赖总量；它不能直接表示从首页切换到该工具时的新增传输量。工具内部继续动态加载的资源和 Worker 单列在运行时资源中。

| 项目 | 2026-10-16 测量 |
| --- | --- |
| 原版 Workbox 构建报告 | 325 项，23,378.79 KiB |
| 新应用壳 | 12 个唯一文件，1,225,840 字节，1,197.11 KiB，约 1.17 MiB |
| 预缓存降幅 | 约 94.9% |
| 首屏启动 JavaScript gzip | 338,143 字节，330.22 KiB，仍高于 300 KiB 目标 |
| 可选入口静态 JS 闭包超标项 | MAC 查询、Text Diff、PDF 签名检查、WYSIWYG 编辑器、数学求值器 |

本片在构建阶段强制执行 8 MiB 预缓存原始大小上限。后续性能工作也在构建阶段强制执行 300 KiB 首屏 JavaScript 与 500 KiB 可选入口闭包 gzip 上限；任一超限都会使生产构建失败。预缓存字节是缓存文件之和，不包含 Service Worker 自身，也不等同于首次安装的总网络传输量。Workbox 日志对自动追加 manifest 的 size 计为 0，完整大小以逐文件测量报告为准。

`pnpm check` 已纳入 `pnpm test:pwa:build` 的清单、路径、去重、预算和缺失资源测试。CI 在校验后上传报告，失败时如报告已生成也会保留。原先手动禁用的独立 E2E workflow 未在本轮启用。

最终验收：`pnpm check` 通过，包含 13 项 PWA 构建边界测试、82 个单元测试文件共 518 项测试、类型检查、零警告 lint 和生产构建。Playwright 离线验收在 Chromium、Firefox、WebKit 共 18 项通过；Docker Nginx 检查通过首页、工具深链、JS/CSS、Service Worker、manifest 和错误响应的安全响应头。自动化浏览器证据来自无头 Playwright；本轮未取得真实桌面窗口证据，Computer Use 尚不能识别用于该项目的真实窗口 URL。

### 2026-10-25 更新：Vite 8 入口预算

Vite 8 使用 Rolldown 生成共享静态块。工具页面的完整闭包会重复计入已载入的应用壳，也会计入尚未启动的 Worker 脚本。因此，500 KiB 预算现在检查从已载入应用壳打开工具时新增的 JavaScript gzip 字节。Worker 脚本继续在运行资源报告中逐项列出。报告保留完整闭包数字，便于检查依赖关系。

新口径没有提高 500 KiB 目标。2026-10-25 的 Web/PWA 构建测得首屏 JavaScript gzip 为 282,397 字节，应用壳预缓存为 1,003,793 字节。117 个工具入口中的最大新增 JavaScript 为 129,569 字节；124 个可选入口均低于 500 KiB。最大 Worker 是 Math Evaluator，gzip 为 187,681 字节。生产构建通过两个预算。
