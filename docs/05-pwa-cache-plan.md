# 应用壳预缓存与访问后离线缓存

日期：2026-10-15。承接 [开发计划](01-development-plan.md) 的第三阶段。先完成第二阶段的验证、提交与推送，再实施本文件。

## 当前证据与范围

本轮安全批次的最终生产构建列出 325 个预缓存文件，合计 23378.87 KiB。后续实施时需要重新测量构建。工具组件已有路由懒加载，但 Workbox 又把全部 JavaScript 和 CSS 加入首次预缓存。最大的候选资源包括 TypeScript worker、MAC 厂商数据和 Text Diff；这些体积来自构建清单，不等同于实际传输量。

本片实现应用壳（Application Shell）的预缓存边界，以及访问后静态资源的运行时缓存（Runtime Cache）。应用壳指入口 HTML、入口的静态 JavaScript 依赖、样式、字体和启动图标。动态工具入口及其专属依赖不进入首次预缓存。运行时缓存只处理同源、构建生成的静态资源，不保存用户内容、工具页面 URL 或第三方响应。

## 实施顺序与验收条件

1. 输出 Vite 构建清单。从 `index.html` 入口递归收集静态 `imports`、CSS 和 assets，去重并排除 `dynamicImports`。用依赖关系筛选 Workbox 候选清单，保留应用启动图标和导航回退入口，不依赖 chunk 名称猜测。
2. 为访问过的同源构建资源增加有数量上限的运行时缓存。保留内容哈希资源的更新边界；升级后清理过期缓存。网络或缓存写入失败不得伪造离线成功。
3. 生成体积报告，明确原始字节和 gzip 字节。首次预缓存原始大小不得超过 8 MiB。报告首屏静态 JavaScript gzip 以及各可选工具入口的静态依赖闭包 gzip；300 KiB 与 500 KiB 的长期目标保留，超标项逐项处理，不调高目标。
4. 增加清单依赖、去重、路径边界、预算失败和缺失资源的定向测试。为生产构建增加离线行为验收：新浏览器首页不下载 MAC、Text Diff 或 Monaco worker；首页可离线重载；联网访问和实际使用过的代表工具可在断网后重载。
5. 通过最终检查后提交并推送。继续检查首屏和大型工具的预算，不把本片完成写成整个第三阶段完成。

## 验证与回滚

执行 `pnpm check`、相关体积报告检查、三浏览器 E2E 和本地 Docker Nginx 的 CSP/响应头检查。离线测试必须等待真实 Service Worker 控制页面，并在独立浏览器上下文验证网络请求和缓存；无 Service Worker 的页面截图不能证明离线可用。真实窗口仍受本轮 Computer Use URL 识别限制，未获得真实窗口证据时明确记录。

本片不变更工具输入、数据格式或远端部署。回滚对应构建配置、缓存辅助代码、报告脚本和测试；浏览器已经安装的旧 Service Worker 需要通过后续版本更新或站点数据清理替换，Git 回退不能直接清除客户端缓存。
