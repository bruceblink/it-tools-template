## 执行与验证

先检查工作区和配置，再修复应用类型。并行审查独立的自动检查配置。所有源文件改动完成后运行：

```sh
pnpm typecheck
pnpm typecheck:app
pnpm lint --max-warnings 0
pnpm test:unit --run
pnpm check
pnpm test:e2e
git diff --check
```

工具注册测试需验证实际注册表，而非复制工具清单。类型修复若涉及可观察行为，增加对应的回归测试。仅改动类型且运行行为不变的文件，不编写重复实现的测试。

本轮不设计新 UI。若类型修复影响输入、搜索、选择或输出，先使用 Computer Use 在本地真实浏览器中验收对应工具。真实窗口不可用时，记录启动检查和 headless 覆盖范围。三浏览器 E2E 不能运行时，明确记录缺失项。Docker 服务集成检查本轮不适用；本轮不部署、不发布。

## 回滚边界

仅回退本轮新增计划、检查入口、类型修复、注册测试和 workflow 变更。保留开发前已有的修改和既有工具数据。构建目录与测试报告属于本地生成结果，不纳入源码交付。后续回退使用审查后的反向补丁，不使用清空工作区的命令。

## 后续顺序

1. 安全与数据边界：Web Crypto 随机源、敏感输入内存默认值、HTML 输出和部署响应头。
2. 性能与 PWA：大型依赖按需加载、应用壳预缓存、离线行为和构建体积预算。
3. 产品与架构：工具能力元数据、语言覆盖、键盘与移动端体验、输入分享和收藏导入导出。

进入下一轮前，先读取本轮记录和工作区状态。尚未通过的检查优先于扩展功能。

安全阶段的首个开发范围已经定位：`token-generator` 使用基于 `Math.random()` 的字符串打乱；UUID 的 v1 参数也使用 `Math.random()`；随机端口调用的整数函数不包含最大值；`jwt-signer` 仍将 secret、payload 和待验证 token 写入本地存储。下一轮先分别完成随机源及边界测试、敏感输入默认内存保存两个可独立验收的范围。测试使用可注入的确定性源和测试数据，不打印真实凭据。

构建剩余提示：`mime-types` 的 `path` 与 `pdf-signature-reader` 的 `tls` 被作为 Node 模块排除出浏览器包；第三方 `iarna-toml`、`js-sha256` 使用 `eval`；UnoCSS 有未匹配工具类；部分 chunk 大于 500 KB；Browserslist 数据较旧。构建退出码为 0。这些提示仍需按工具运行边界和第三阶段的体积预算分别处理，不能据此声明所有工具的依赖行为已验收。

Windows 验证环境说明：本机 Codex 安装环境会重定向 AppData 浏览器缓存路径。Firefox 从虚拟路径启动时出现 `spawn UNKNOWN` 和 Windows SideBySide 错误 14001；同一程序使用 `fs.realpathSync.native()` 返回的实际路径可以启动。复测只在测试命令进程内设置 `PLAYWRIGHT_BROWSERS_PATH` 指向实际缓存目录，不修改项目的浏览器版本、系统设置或浏览器程序。

后续已发现一项元标签输出检查：当前 `@it-tools/oggen@1.3.0` 对 `{ type: 'music.song' }` 生成 `<meta property="og:type" value="music.song" />`。本轮分组选项测试验证选中的叶子值，不验证该第三方生成器的全部 HTML 语义。下一轮工具正确性检查需覆盖这项输出。
