# 对象存储传输开发计划

> 日期：2026-10-24
> 主线：PRODUCT-WORKBENCH-001
> 状态：已完成（无头验证）

## 范围与验收

在现有 S3 兼容工作台中增加文件上传、文件下载和单个对象删除。主进程通过系统文件对话框选择源文件和保存位置，不接受渲染器传入的本机路径。每个窗口仍只有一个连接和一个活动操作。

- 上传和下载使用流式处理、背压、进度和取消。单个文件最多 1 GiB，单次传输最多 5 分钟；列表和预览继续使用原有 10 秒限制。
- 默认上传不能覆盖已有对象。用户选择替换后，由主进程显示包含 Bucket 和对象键的确认对话框。删除同样需要主进程确认。取消对话框不改变远端对象。
- 下载先写目标目录中的独占临时文件，成功后替换目标。失败、取消、超限或窗口关闭时删除临时文件，保留已有目标文件。
- 进度仅发给操作所属窗口。切换路由、断开、替换连接和退出均终止活动请求并关闭本机文件。错误返回固定代码，不包含凭据、连接正文或 SDK 原始错误。
- 页面提供上传目标键、覆盖选项、上传按钮、对象下载/删除图标、传输进度、成功和失败结果。Web 不包含新增 IPC、SDK 或页面。

目录递归、分段上传、断点续传、Bucket 管理和对象版本管理不属于本片；这些限制不改变当前只读浏览功能。

## 验证与回滚

定向测试覆盖文件上限、下载原子替换、取消后的临时文件清理、已有对象保护、会话归属和拒绝确认。使用本机 Docker RustFS 1.0.1 的 Electron E2E 验证上传、覆盖、下载字节一致性、进度和删除，记录端口和清理结果。执行 pnpm check，并复查桌面与窄窗口布局。Computer Use 优先；无法取得完整真实窗口证据时明确记录范围。

每个独立功能验证后提交，不推送。回滚只撤销本片，保留前一片对象浏览、已有工具及用户文件。

## 实施结果

主进程使用系统文件对话框选择本机路径。上传通过条件写入保护已有对象；用户启用替换时，主进程先确认 Bucket 和对象键。下载使用有界流和背压，并在目标目录写入随机独占临时文件。下载完成且字节数与服务端长度一致后，临时文件才会替换目标文件。取消、超限、超时或本机 I/O 错误会删除临时文件，并返回固定错误码。

页面提供目标对象键、替换选项、上传、下载、删除、进度、取消、成功和失败状态。390×844 无头 Electron 页面隐藏修改时间列，并保持对象键、字节数和行操作可读；检查没有横向溢出。此无头结果不作为真实窗口交互证据，真实窗口验收未完成。
