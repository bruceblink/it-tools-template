# 第一方扩展 SDK v0

本文记录仓库内第一方扩展 SDK 的接口、限制和样例。SDK API 版本为 `0.1.0`。本实现供项目维护的代码使用，不提供第三方代码隔离，也不提供用户安装界面。

## 扩展包结构

扩展包先注册静态 `ExtensionManifest`。宿主检查包 ID、包版本、API 兼容范围、平台入口、激活事件、贡献项和能力声明。注册阶段不加载实现模块。

清单使用 `minInclusive` 和 `maxExclusive` 表示宿主 API 兼容区间。版本只接受稳定的 `MAJOR.MINOR.PATCH` 格式。当前 API `0.1.0` 适用于 `0.1.0 <= hostApi < 1.0.0`。

实现模块通过动态 `import()` 加载。宿主只接受清单中声明的事件：

- `onTool:<namespace>/<tool>`：首次打开对应工具时激活。
- `onCommand:<namespace>/<command>`：运行对应命令时激活。
- `onSetting:<namespace>/<setting>`：读取或更新对应设置时激活。
- `onData:<namespace>/<provider>`：读取对应数据源时激活。

工具、命令、设置和数据源 ID 都必须位于扩展命名空间内。扩展包在实现加载前提供静态工具分类和路由定义。复用现有工具时，扩展 ID 映射到原有 URL 与分类，以保留书签和收藏；新增工具可使用 `/extensions/<package-slug>/<tool-slug>`。宿主注册和激活时都会检查 ID、分类、路径、别名、能力及其与静态定义的一致性。第一方样例显式携带治理元数据，因此生产构建裁剪内置工具字段后，扩展宿主仍可校验静态定义。

清单中的搜索命令只包含本地化标题、说明、关键词和站内目标路由。用户首次打开命令面板时，宿主才加载第一方命令目录。用户选择命令时，宿主再加载对应的扩展实现。进入归属扩展包的工具路由时，路由守卫也会按需加载宿主并激活对应工具事件。样例命令仍打开现有工具页面。

## 生命周期和权限

扩展状态包括 `registered`、`activating`、`active`、`failed` 和 `disabled`。并发激活共享同一个激活任务。扩展注册的清理函数按逆序执行。一个包激活失败时，宿主清理该包的资源；其他包仍可独立激活。

命令声明的能力必须同时出现在清单请求中，并由宿主授予。未授权的命令不会运行。工具能力目前用于注册审查和 UI 展示，不能限制同进程 JavaScript 自行访问浏览器 API。因此这些声明不是安全边界。

扩展包属于受信任的第一方代码。SDK 不加载远程包，不执行 npm 安装脚本，也不提供进程隔离。不能用本 SDK 运行不可信的第三方扩展。Electron 原生能力仍应通过现有受限 Platform Adapter；本轮没有向扩展公开主进程 IPC。

## 设置和数据提供器

设置只支持字符串、有限数值和布尔值。字符串默认最多 1,024 个字符，清单可把上限设为 4,096 个字符。数值可声明最小值、最大值和整数约束。清单可定义本地化标签与说明。浏览器和 Electron 使用按扩展与设置 ID 隔离的本地存储键，并以 `{ schemaVersion, value }` 保存设置。旧版原始值按版本 1 读取；迁移定义必须覆盖从当前存储版本到目标版本的每个连续版本。宿主按版本顺序执行转换，并校验迁移结果。迁移成功后写回目标版本。迁移失败时使用默认值并保留旧记录；若记录来自较新应用版本，也使用默认值并保留记录。

全局设置页面位于 `/settings`，从顶部导航的齿轮图标按需打开。旧地址 `/settings/extensions` 会重定向到该页面。页面先显示语言和主题，再显示各扩展在清单中声明的设置；设置支持编辑、保存、恢复默认值和版本迁移。若一个扩展包设置加载失败，其他包的设置仍可使用。浏览器存储不可用时，值只保留在当前进程内存中。设置只适合普通偏好，不应用于凭据或秘密数据，也不会跨设备同步。

数据提供器声明稳定数据版本、正整数 `schemaVersion` 和最大字节数。宿主限制每个数据结果不超过 8 MiB，并拒绝不可序列化或超过提供器上限的结果。读取返回的快照包含提供器 ID、数据版本和结构版本。HTTP 状态码表由应用构建时提供。OUI provider 复用现有同源清单和分片校验，只读取匹配 MAC 前缀的一个分片。当前 OUI 数据版本为 `1.2.0`。读取会接收扩展生命周期的取消信号。一次网络失败或数据超限只使本次读取失败，调用者可以重试；宿主不因此停用整个扩展。离线查询仍只保证已缓存的分片可用。

## 第一方样例

`src/extensions/samples/` 中的三个包复用现有工具定义，并经过同一宿主校验：

| 扩展包 | 复用能力 | SDK 增量 |
| --- | --- | --- |
| `org.it-tools.data-conversion` | JSON Lines、CSV 转换 | 汇总 JSON Lines 有效与无效行，并声明记录数设置 |
| `org.it-tools.network-security` | HTTP 头、CORS、CSP 分析 | 汇总安全响应头覆盖情况，并声明显示设置 |
| `org.it-tools.offline-reference` | OUI、MIME 与 HTTP 状态查询 | 暴露 HTTP 状态码表和版本化 OUI 查询 provider |

样例工具和数据源通过 SDK 校验。命令目录在用户打开命令面板时按需加载。三个无输入命令分别打开现有 JSON Lines、安全响应头和 HTTP 状态码工具。9 个样例工具已进入应用生产路由和导航；它们保留原路径、分类、别名和收藏行为，扩展包实现在进入所属工具路由时才激活。持久设置已按扩展 ID 和设置 ID 写入本地存储；受限浏览器存储不可用时，SDK 使用当前进程内存。数据转换样例的最大记录数设置现为 schema version 2；迁移会把版本 1 的有限数值向下取整。设置管理页面可显示迁移成功、迁移失败和较新版本提示。失败或较新版本的数据不会被覆盖。

## 验证

`src/extensions/extension-host.test.ts` 覆盖 API 兼容范围、平台和入口校验、延迟加载、搜索命令声明、静态路由登记和激活、能力授权、设置迁移、OUI 分片 provider、数据大小、并发激活、资源逆序释放、失败恢复和包间故障隔离。`src/extensions/samples/tool-scope.test.ts` 检查生产工具投影缺少治理字段时，样例包仍会提供完整静态元数据。`src/extensions/route-activation.test.ts` 检查按路由激活宿主。`pnpm check` 通过 96 个测试文件、599 项测试、类型检查、lint、Web 构建和 Electron 构建。System Chrome 的扩展路由与 PWA 端到端回归 8 项通过；设置页面迁移、保存和重载回归 1 项通过。`pnpm test:e2e:electron` 9 项通过，包含设置迁移、保存、重载、扩展工具路由和 P5 沙箱原型。Computer Use helper 无法初始化，所以本轮没有手工截图验收；Electron 自动化窗口流程通过。
