# 随机源与敏感输入开发计划

日期：2026-10-15。分支：当前 `main`。本轮完成两个独立任务，验证、提交并推送后按用户要求关闭电脑。长期顺序见 [开发计划](01-development-plan.md)。

## 术语与范围

- 随机源（RandomSource）：向随机算法提供随机字节的接口。默认实现使用 Web Crypto；测试实现提供确定性测试数据。该接口不负责保存输入或生成 UUID 的时间字段。
- 敏感输入（Sensitive Input）：JWT 签名器的密钥、头部、载荷和待验证 token。本轮不增加账号、同步或“记住输入”功能。

## 任务一：安全随机源与边界

统一随机辅助函数的默认随机源。检查 token、OTP secret、UUID 和随机端口的调用点，移除这些路径中的 `Math.random()`。通用整数函数保留现有半开区间；端口范围显式包含两端。使用无取模偏差的抽样。校验非法范围；随机源不可用时明确失败，不回退到非安全随机源。

默认随机源遵循 [Web Crypto 的 getRandomValues 定义](https://w3c.github.io/webcrypto/#Crypto-method-getRandomValues)。该方法填充调用者提供的整数数组，单次字节数不得超过 65536；实现和测试需保留这项资源限制。

UUID v1 的随机节点标识按 [RFC 9562 第 6.10 节](https://www.rfc-editor.org/rfc/rfc9562.html#section-6.10) 设置首字节的最低位；版本、变体和批量生成结果由确定性测试检查。

验收条件：

- 随机源可以注入确定性测试数据；默认实现调用 Web Crypto。
- 测试覆盖上下界、非法参数、拒绝抽样及随机源失败。
- 随机端口能够生成范围最大值 `65535`，保留现有范围和预设的含义。
- token、OTP secret 和 UUID 保持现有格式、数量与工具路径。

## 任务二：JWT 敏感输入默认保存在内存

将签名密钥、头部、载荷、待验证 token 和验证密钥改为页面内存状态。算法选择仍可保存。清理本工具旧版本对应的五个本地存储键，不读取或记录旧值，也不修改其他工具的存储。存储不可用或清理失败时，页面仍使用内存状态，并说明清理结果。

验收条件：

- 编辑、签名和验证均不将敏感字段写入本地存储或会话存储。
- 刷新页面或离开后重新进入时，恢复默认测试内容，不恢复刚输入的敏感数据。
- 旧敏感键被清理；算法选择和无关设置保留。
- 测试覆盖签名、验证、刷新、路由切换及存储访问失败。
- 页面用简短说明告知输入的保存范围，英文和中文说明齐全。

## 实施与验证

先完成当前质量基线的 WebKit 字体请求修复，再实施上述两个任务。每个任务完成后运行对应单元测试；对最终源码运行：

```sh
pnpm check
pnpm test:e2e
git diff --check
```

浏览器验收使用本地生产构建。真实窗口受 Computer Use 限制时，保留明确限制并运行三浏览器 headless 测试。外部服务集成、Docker 服务、部署和发布：不适用。推送后核对现有 CI；远端 E2E 工作流的手动禁用设置保持不变。

## 提交与回滚边界

质量基线、随机源和敏感输入分别形成可审查提交。完成两个任务并通过最终检查后再提交、推送。仅回退对应功能的源文件、测试和文档，不清空工作区。旧敏感数据清理属于运行时隐私修复，不备份、不记录，也不能通过代码回退恢复。测试只使用公开的测试数据。

## 实施记录

状态：任务一已实现并通过定向检查。任务二的实现和本轮最终统一验收随下一项独立提交记录。

任务一已实现：

- `RandomSource` 使用字节填充回调。默认源按需访问 Web Crypto，调用失败会向上传递；每次最多分配 65536 字节。
- 整数选择使用 32 位拒绝抽样，连续拒绝 128 次后报错。通用半开区间和单点行为保持；端口模型将闭区间映射为半开区间。
- token 按字母表索引逐个抽样，不再构造重复字母表。非空 token 最多 65536 个 UTF-16 代码单元；空字母表、零长度和原有小数截断行为保留。
- OTP secret、UUID v1/v4、MAC 默认生成和共享随机工具使用同一随机源。UUID v1 随机节点标志位有确定性测试。
- 6 个定向测试文件的 53 项测试、应用类型检查和分配文件的 ESLint 已通过。生产源码未检出 `Math.random()` 或 `_.random()` 调用。
