# 插件市场安装流程

本文定义插件市场、Electron 宿主和 GitHub 仓库之间的安装边界。市场仍是只读导航，不保存、代理或执行插件包；插件源码和发布资产继续由各自的 GitHub 仓库负责。

## 目标体验

用户从市场卡片开始，能够在一个连续流程中完成发现、审查、安装和运行：

1. 市场查询带有 `it-tools-plugin` topic 的 GitHub 仓库，展示仓库、`plugin.source.json` 和发布版本的参考信息。
2. Electron 用户点击“安装最新版本”后，宿主重新读取仓库元数据，固定到一个 release asset 和 commit/tag，不使用可变的默认分支内容。
3. 宿主在主进程通过 HTTPS 下载 `.itplugin`，限制大小和重定向，校验包清单、文件哈希、API 兼容范围和签名。
4. 签名者未受信任时，流程停在“需要核对发布者指纹”；信任签名者不会自动授予插件能力。
5. 安装完成后，管理器显示包 ID、版本、来源版本和能力摘要；用户选择能力并确认桌面授权提示后才运行插件。

市场只提供仓库和发布资产的参考链接。安装过程不把包写回市场，也不让 Web 页面直接访问本机文件系统。

## 两种安装模式

### 普通用户：已签名 release 直装

这是默认入口。仓库发布 `.itplugin` 资产，并在 README 或发布说明中提供签名者公钥指纹。Electron 只下载 release 资产，复用现有安装器完成校验和暂存。

- 下载在主进程执行，渲染器只传递经过校验的仓库身份。
- 允许的来源限定为 GitHub API、GitHub release asset 或仓库声明的同源 HTTPS 地址。
- 下载完成后先写入随机临时目录；验证失败、取消或安装失败都会清理临时文件。
- 安装器拒绝已归档、fork、缺少 `it-tools-plugin` topic、超出大小上限或版本已经存在的仓库。
- 签名、哈希、能力授权和隔离窗口规则与本地 `.itplugin` 安装完全一致。

### 开发者：固定源码快照构建

源码构建用于开发和审查，不作为普通市场安装的静默回退：

1. 宿主下载固定 commit 的源码快照，校验 GitHub 返回的仓库和 commit 身份。
2. 源码先落到临时目录并执行 `plugin:validate`；需要 TypeScript 时使用 `plugin:build --tsconfig <project.json>` 完成 `--noEmit` 检查和签名打包。
3. 管理器显示“本地构建”标识、仓库、commit、构建时间和签名者。用户明确确认后才安装。
4. 不使用应用自身的长期私钥替源码自动签名；开发者必须提供仓库外的签名密钥，或者使用独立的本地开发签名者并明确标记其身份。

Electron 不在普通模式下直接加载 GitHub 原始 HTML/JavaScript。直接加载会绕过固定包清单、文件哈希和发布者身份，也会让可变分支内容进入宿主生命周期。若未来增加源码预览，只能使用无持久安装、无宿主能力、无工具注册的独立预览窗口。

## 状态模型

市场安装按钮和管理器共用以下状态，避免把“下载完成”误报为“已安装”：

| 状态 | 含义 | 用户动作 |
| --- | --- | --- |
| `discovering` | 正在重新读取仓库和 release 元数据 | 等待或取消 |
| `pinned` | 已固定仓库、版本和 commit/tag | 查看来源摘要 |
| `downloading` | 正在下载临时资产 | 等待或取消 |
| `verifying` | 正在校验包、哈希、API 和签名 | 等待 |
| `awaiting-trust` | 包有效但签名者尚未受信任 | 核对指纹并添加公钥 |
| `installed` | 包已写入版本目录，尚未运行 | 选择能力并运行 |
| `active` | 插件窗口正在运行 | 停止或查看能力 |
| `failed` | 下载、校验或安装失败 | 按错误码重试或改用仓库说明 |

每个失败结果保留稳定错误码和下一步动作。网络错误不应让半成品目录出现在已安装列表中；签名错误不应自动降级为源码直装。

## 仓库发布约定

市场发现至少需要：

- `it-tools-plugin` topic；
- `plugin.source.json`，用于展示 API 范围、能力和工具贡献；
- 清楚的 README，说明发布者、公钥指纹、安装方式和能力用途。

推荐发布 `.itplugin` release asset，并在 release 说明中列出包版本、SHA-256 和签名者指纹。后续可以增加 `plugin.release.json` 作为机器可读摘要，但它只描述资产和来源，不替代包内签名。

## 分阶段交付

1. **已完成基础**：市场只读 GitHub 目录、Electron 本地包安装、信任、能力授权和生命周期管理；`plugin:build` 将源码校验、可选 TypeScript 检查和签名打包收敛为一个命令。
2. **下一步**：增加 Electron 的“从 GitHub release 安装”IPC，主进程完成来源校验、下载、临时文件清理和现有安装器复用；市场卡片增加直装按钮和状态反馈。
3. **后续开发模式**：固定 commit 的源码下载和显式本地构建，补充来源摘要、取消、重试和构建签名者显示；不开放普通模式的原始源码直载。

验收必须覆盖仓库身份伪造、可变分支、重定向、超大资产、取消清理、签名不受信任、重复安装、能力拒绝和安装后运行恢复。
