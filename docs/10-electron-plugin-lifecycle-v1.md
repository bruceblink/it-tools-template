# Electron 插件生命周期服务 v1

本文记录 `electron/plugin-lifecycle.ts` 的职责和运行边界。该服务属于 P5 隔离试点，尚未接入主进程 IPC 或桌面管理界面。调用方负责提供受信任签名公钥和插件安装根目录。

## 操作流程

1. `installArchive()` 调用签名包安装器。它验证包签名、API 兼容范围、ZIP 条目和文件哈希，再把静态资源暂存到调用方提供的安装根目录。安装不会执行插件脚本。
2. `listInstalled()` 扫描安装根目录，并验证每个 `plugin.json` 的签名和 API 版本。清单无效的包会以 `invalid` 状态返回。此步骤不读取每个资源文件的完整内容。
3. `activate()` 在启动窗口前重新检查插件身份、签名、目录内容和每个受签名保护文件的 SHA-256。它拒绝额外文件、缺失文件、符号链接、硬链接、特殊文件和越界目录。
4. 宿主传入本次激活的能力授权。授权必须同时属于插件清单的请求范围和当前宿主支持的范围。当前服务只支持 `runtime.info` 与 `clipboard.write`。
5. 每个插件 ID 同时只运行一个版本。激活新版本时，服务先销毁旧窗口，再打开新窗口。新窗口启动失败时，服务会重新验证旧版本并尝试恢复。
6. `disable()` 销毁该插件的活动窗口。`uninstall()` 会在必要时先停用插件，然后只删除安装根目录内指定版本的目录。其他已安装版本保留。

## 限制和失败处理

- 安装包上限为 128 个插件版本，同时最多运行 4 个插件窗口。
- 插件包路径最多有 32 个段。该限制也控制启用前的目录检查量。
- 插件入口必须在 15 秒内加载。Electron 报告窗口持续无响应 10 秒后，服务会销毁该窗口。
- 插件窗口必须在 5 秒内关闭。超时会使停用、升级或卸载失败，避免服务错误报告插件已退出。
- 插件关闭会触发沙箱清理并撤销本次窗口的能力授权。授权不跨应用重启保存。
- 服务不会在应用启动时自动运行已安装插件。插件必须由后续管理界面明确启用。
- 安装的公钥列表由调用方注入。当前应用没有生产签名公钥、本地信任密钥存储或公钥管理界面，因此生产 IPC 尚不能安装包。
- 新版本失败后，若旧版本文件或签名也已损坏，服务会报告 `activation-rollback-failed`，并保持插件停止。

## 验证

`electron/plugin-lifecycle.test.ts` 覆盖签名包安装、启用前完整性检查、能力授权、活动插件数量上限、版本启动失败后的恢复，以及停用活动窗口后按版本卸载。包签名和 ZIP 安全边界由 `electron/plugin-package.test.ts` 另行覆盖。
