# 对象存储工作台设计说明

> 日期：2026-10-24
> 主线：PRODUCT-WORKBENCH-001
> 状态：开发与自动化回归完成；Computer Use 完整流程待验收

## 范围

新增 Electron 专属 S3 兼容对象存储工作台。用户填写服务地址、区域、Bucket 和临时连接凭据后，可以按前缀分页查看对象，并预览受限的 UTF-8 文本。复用现有工具注册、平台适配层和主进程 IPC 模式。使用 AWS SDK 处理 S3 协议。

连接凭据只保存在当前页面和主进程会话内存中，不写配置、历史、日志或错误消息。每个渲染器最多保留一个连接和一个活动操作。连接替换、断开、取消、页面卸载、窗口关闭和应用退出都必须释放活动请求与客户端。

Bucket 是对象存储中的对象容器，本片必须由用户明确指定名称，不枚举账户中的全部 Bucket。对象键（Object Key）是 Bucket 内的完整名称，不作为本机文件路径解析。分页令牌（Continuation Token）仅传回同一服务，不写入历史或配置。

此设计不包含 Bucket 管理、凭据保存、COS/OSS 专用协议或容器工作台。

## 验收条件

- 连接指定 Bucket，按前缀列出每页最多 100 个对象，并支持下一页和返回第一页。
- 单次请求最多 10 秒；列表响应最多 1 MiB；对象预览最多读取 64 KiB。二进制内容不作为文本或 HTML 执行。
- 明确显示连接、空结果、运行中、取消、权限拒绝、网络错误、超时和预览截断状态。失败后清空旧结果。
- 主进程校验来源、参数长度和会话所有者。仅接受 HTTPS 或本机回环 HTTP 地址。SDK 只对用户指定服务发送签名请求，不自动切换区域或跟随重定向。
- Web 不注册工具，不包含 S3 SDK、桌面桥或页面代码；直接访问路由返回 404。首屏 gzip 继续低于 300 KiB。
- 本机 Docker 中的 S3 兼容服务覆盖真实连接、分页、前缀、预览、拒绝访问及资源清理。记录镜像版本、端口、启动和清理结果。

## 传输设计与验收

文件上传、下载和单个对象删除沿用同一连接、来源校验和会话所有者边界。主进程通过系统文件对话框选择源文件和保存位置，不接受渲染器传入的本机路径。每个窗口最多保留一个连接和一个活动操作。

- 上传和下载使用流式处理、背压、进度和取消。单个文件最多 1 GiB，单次传输最多 5 分钟；列表和预览继续使用 10 秒限制。
- 默认上传不能覆盖已有对象。用户选择替换后，主进程显示包含 Bucket 和对象键的确认对话框；删除也必须确认。取消确认不改变远端对象。
- 下载先写目标目录中的随机独占临时文件。只有服务端长度和实际字节数一致时才替换目标；失败、取消、超限、窗口关闭或本机 I/O 错误时删除临时文件并保留已有目标。
- 进度只发送给所属窗口。切换路由、断开、替换连接和退出会终止活动请求并关闭本机文件。错误使用固定代码，不返回凭据、连接正文或 SDK 原始错误。
- 目录递归、分段上传、断点续传、Bucket 管理和对象版本管理不属于当前设计。

## 验证

先执行协议与生命周期定向单测，再执行 pnpm check。Electron 定向 E2E 使用本机 Docker 服务，不以模拟服务替代集成证据。Web 定向 E2E 检查入口隐藏和 404。真实窗口先使用 Computer Use；不可用时执行有限的恢复检查，并单独报告自动化窗口证据。Browser 插件未提供，浏览器自动化使用仓库现有 Playwright。

目标流程：/object-storage -> 连接本机 Bucket -> 查看对象和下一页 -> 按前缀筛选 -> 预览文本 -> 断开后清空结果。

## 实施记录

- `/object-storage` 仅在 Electron 注册。AWS SDK 3.1156.0 和 Node HTTP handler 4.12.1 只在主进程加载。来源校验拒绝插件和外部页面。S3 Express 自动会话、区域重定向和重试均关闭。
- 页面包含连接状态、Bucket、服务地址、前缀筛选、第一页、下一页、文本预览、取消和断开。内容以纯文本显示，HTML 不执行。零字节对象先检查元数据，不发送无效 Range 请求。
- 列表每页 100 个对象；原始响应最多 1 MiB；预览输出最多 64 KiB；单次操作最多 10 秒。响应流采用背压，达到预览上限后关闭流和套接字。客户端不保存连接配置或凭据。
- 英文和中文桌面语言文件与 Web 分开构建。API、Git 和系统监视器文案迁到桌面语言文件，避免占用 Web 首屏体积。其他语言继续使用现有英文回退。
- `pnpm install --frozen-lockfile` 通过。完整 `pnpm check` 通过 123 个测试文件、756 项测试；2 个测试文件和 18 项测试按现有条件跳过。包含类型检查、零 warning lint、Web 构建、Web 隔离检查和 Electron 构建。
